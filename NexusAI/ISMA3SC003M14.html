NexusAI

일을 맡기면, 여러 AI가
역할을 나눠 처리합니다

NexusAI는 여러 AI 에이전트를 한 화면에서 만들고, 일을 나눠 맡기고, 결과를 모아 보는 플랫폼입니다. 만드는 방식이 서로 다른 에이전트 개발 도구 10종을 같은 방법으로 쓸 수 있게 연결했습니다. 어떤 AI 모델이 일을 처리하는지, 그때 데이터가 어디로 가는지도 구분해 보여 드립니다.

Overview

도구는 많은데,
쓰는 법이 제각각입니다

AI 에이전트를 업무에 붙여 보려고 하면 먼저 도구 선택에서 막힙니다. 에이전트를 만드는 도구가 여럿이고, 저마다 쓰는 법과 잘하는 일이 다르기 때문입니다.

AI 에이전트는 정해 준 역할 안에서 스스로 판단해 일을 수행하는 AI 프로그램입니다. 이것을 만드는 개발 도구를 프레임워크라고 부릅니다. 프레임워크마다 설정 방식이 달라서, 하나를 시험해 본 뒤 다른 것으로 바꾸려면 다시 만들어야 합니다. 어떤 AI 모델을 쓰는지, 회사 자료가 어디로 전송되는지도 도구마다 따로 확인해야 합니다.

NexusAI는 이 차이를 한 화면 뒤로 감춥니다. 사용자는 에이전트의 이름과 역할, 목표를 적고 프레임워크와 모델을 고르기만 하면 됩니다. 일이 크면 여러 역할의 에이전트에게 나눠 맡기고, 결과는 하나로 모아 받습니다. 이렇게 여러 에이전트의 일을 배분하고 순서를 맞추는 것을 오케스트레이션이라고 합니다.

쉽게 말하면

여러 전문 업체를 한 창구에서 부르는 종합 접수 창구와 같습니다. 접수는 한 곳에서 하고, 일은 맞는 담당에게 나뉘어 가며, 결과는 다시 한 창구로 돌아옵니다.

NexusAI에서 전문 업체는 프레임워크와 AI 모델이고, 접수 창구는 에이전트 관리 화면입니다. 창구는 누구에게 맡길지 정하고, 순서를 맞추고, 결과를 모읍니다.
도구가 여럿이어도만드는 법은 하나

이름, 역할, 목표, 배경 설명을 적으면 에이전트가 만들어집니다. 프레임워크를 바꿔도 입력하는 항목은 같습니다.

큰 일은역할로 나눠서

기획 역할이 일을 작은 작업으로 쪼개고, 조사·분석·실행·검토 역할이 순서에 맞춰 처리합니다. 앞 작업의 결과는 다음 작업에 전달됩니다.

모델과 데이터는가는 곳을 구분

클라우드 모델을 쓰면 입력 내용이 그 제공사로 전송됩니다. 사내 장비의 로컬 모델로 처리할 수 있는 범위는 따로 정해져 있습니다.

연결 안 된 기능은안 됐다고 표시

외부 서비스가 필요한 기능은 연결 전까지 「미설정」이나 「예시 데이터」로 표시합니다. 성공한 것처럼 꾸민 결과를 내지 않습니다.

How it works

한 문장의 요청이
나뉘고, 다시 모입니다

여러 역할이 함께 처리하는 「협업 워크플로」의 흐름입니다. 워크플로는 일을 처리하는 순서를 정해 둔 작업 흐름을 뜻합니다. 요청을 넣으면 계획이 먼저 나오고, 실행은 그다음에 시작됩니다.

  1. 요청

    맡길 일을 문장으로 적습니다. 일의 난이도와, 꼭 참여시키고 싶은 역할이 있으면 함께 지정합니다.

    사람이 입력
  2. 계획

    AI가 요청을 작은 작업으로 나누고, 작업마다 맡을 역할과 선행 작업을 정합니다. 이 계획은 실행 전에 화면에서 확인할 수 있습니다.

    기획 역할 · AI
  3. 실행 지시

    계획을 확인한 뒤 실행을 시작합니다. 같은 일이 이미 실행 중이면 두 번째 실행 요청은 거절되어, 같은 작업이 중복 처리되지 않습니다.

    사람이 시작
  4. 역할별 처리

    선행 작업이 끝난 작업부터 처리합니다. 서로 기다릴 필요가 없는 작업은 동시에 진행합니다. 각 역할은 앞선 작업의 결과를 참고 자료로 받습니다.

    조사 · 분석 · 실행 · 검토 역할
  5. 종합

    역할별 결과를 하나의 최종 답으로 정리합니다. 도중에 모델 호출이 실패하면 그 일은 「실패」로 표시됩니다.

    AI
  6. 검토

    결과는 초안입니다. 검토 역할의 AI가 한 번 살펴보지만, 사실 확인과 최종 판단은 담당자가 합니다.

    사람이 확인
AI 에이전트가 처리사람이 입력하거나 확인
Frameworks & models

어댑터는 해당 프레임워크가 서버에 설치되어 있고 그 제공사의 API 키가 등록된 경우에만 동작합니다. 조건이 맞지 않으면 「직접 실행」으로 대체되고, 그 사실은 서버 기록에만 남습니다. 도입할 때 실제로 쓸 프레임워크를 정해 설치 상태를 확인해야 합니다. 프레임워크 어댑터는 현재 클라우드 모델만 사용하며, 각 어댑터는 에이전트 하나의 실행을 맡습니다.

Features

만들고, 나눠 맡기고,
업무 도구에 잇습니다

에이전트를 만드는 화면에서 시작해, 여러 역할의 협업, 부서별로 준비된 업무 스킬, 외부 업무 도구 연결까지 한 곳에서 다룹니다. 화면은 한국어와 영어로 제공됩니다.

역할을 나눠 처리하는 협업 워크플로

한 번에 답하기 어려운 일을 다섯 역할의 에이전트가 나눠 처리합니다. 계획 단계에서 작업 사이의 선후 관계가 정해지고, 실행 단계는 그 순서를 지킵니다. 이 기능은 Anthropic의 클라우드 모델로 동작합니다.

  • 기획 — 일을 작업으로 나누고 순서를 정함
  • 조사 — 필요한 정보를 모아 정리
  • 분석 — 모은 내용에서 의미를 찾아냄
  • 실행 — 계획에 따라 결과물을 작성
  • 검토 — 품질을 살피고 보완점을 제시
  • 진행 상태와 역할별 결과를 화면에서 조회

에이전트 만들기

코드를 쓰지 않고 화면에서 에이전트를 만듭니다. 실행할 때마다 결과와 걸린 시간이 이력으로 남습니다.

  • 이름, 역할, 목표, 배경 설명 입력
  • 프레임워크와 모델 제공사 선택
  • 미리 준비된 템플릿에서 시작
  • 본인이 만든 에이전트만 조회·수정

부서별 업무 스킬

부서에서 자주 하는 일을 스킬로 묶어 두었습니다. 스킬을 고르고 내용을 입력하면 AI가 그 업무 형식에 맞춰 결과를 작성합니다.

  • 11개 업무 영역, 19개 부서, 67개 스킬
  • 여러 부서가 함께 쓰는 공통 스킬 8개
  • 사내 로컬 모델을 먼저 사용

Google Workspace 연결

서버에 설치한 Google Workspace 명령줄 도구(gws)를 거쳐 메일, 일정, 문서를 NexusAI 화면에서 다룹니다.

  • Gmail, Calendar, Sheets, Docs, Drive 등 11종
  • 스탠드업 보고, 회의 준비 등 묶음 작업 5종
  • 도구 설치와 Google 계정 인증이 필요

승인을 거치는 명령 실행

하고 싶은 일을 문장으로 적으면 AI가 서버 명령 계획을 만들고, 위험도에 따라 승인을 요청합니다.

  • 조회성 명령은 자동, 그 밖은 사람의 확인
  • 시스템을 망가뜨릴 수 있는 명령은 차단
  • 격리 환경이 아닌 서버에서 직접 실행
Deliverables

맡긴 일은
기록과 함께 돌아옵니다

결과와 함께, 어떤 방식으로 처리했는지, 얼마나 걸렸는지, 실패했다면 그 이유가 남습니다.

결과물담기는 내용쓰임새
에이전트 실행 결과에이전트의 답, 선택한 프레임워크, 걸린 시간, 실패 시 오류 내용같은 일을 다른 프레임워크나 모델에 맡겨 결과를 견주어 봅니다.
협업 계획작업 목록, 작업별 담당 역할, 선행 작업실행 전에 일이 어떻게 나뉘었는지 확인합니다.
협업 결과역할별 작업 결과와 이를 종합한 최종 답보고서나 기획안의 초안으로 쓰고, 담당자가 검토해 확정합니다.
부서 스킬 결과선택한 스킬의 형식에 맞춘 문서 초안과 처리 시간반복되는 문서 작업의 첫 원고를 줄입니다.
Google Workspace 작업보낸 메일, 만든 일정, 추가한 시트 행, 작성한 문서결과가 실제 Google 계정에 반영됩니다.
명령 실행 기록AI가 세운 명령 계획, 승인 등급, 실행 결과누가 무엇을 승인해 실행했는지 되짚습니다.
대화 이력주고받은 내용과 토큰 수사용량을 가늠합니다. 토큰은 모델이 글의 양을 세는 단위입니다.

협업 워크플로의 진행 상태는 서버 메모리에 보관되어, 서버를 다시 시작하면 사라집니다. 필요한 결과는 따로 저장해 두어야 합니다. 분석 화면의 일부 지표와 부서 스킬 화면의 일부 통계는 예시 데이터이며, 화면에 그렇게 표시되어 있습니다.

Principle

연결되지 않은 것을
된 것처럼 보이지 않는다

여러 도구를 한데 묶은 플랫폼에서는 「메뉴가 있다」와 「실제로 동작한다」가 구분되어야 합니다.

NexusAI는 자체 점검에서 흉내만 내던 기능을 찾아 실제 구현으로 바꾸거나, 그럴 수 없는 것은 「미설정」, 「미구현」, 「AI가 생성한 내용」으로 표시하도록 고쳤습니다. 아래는 형식 검증에서 확인한 내용과 현재 구성의 한계입니다.

CASE · 협업 워크플로의 형식 검증

같은 일이 두 번 실행되지 않는가

협업 워크플로의 실행 순서를 수학적 모델로 옮겨, 가능한 경우를 정해진 범위 안에서 빠짐없이 따져 보는 모델 검사를 적용했습니다. 같은 일에 실행 요청이 동시에 두 번 들어오면 모든 작업이 두 번씩 처리되는 결함 1건을 찾았습니다.

FIXED실행 중인 일의 재실행을 거절하도록 고치고, 수정 전에는 실패하고 수정 후에는 통과하는 재현 시험으로 확인했습니다. 검사한 범위 안에서의 결과입니다.
LIMITS · 현재의 한계
  1. 프레임워크는 대부분 클라우드 모델을 씁니다프레임워크 어댑터와 협업 워크플로를 쓰면 입력 내용이 해당 모델 제공사로 전송됩니다.
  2. 일부 완료 표시는 사람이 확인해야 합니다AI가 계획을 만들지 못해 기본 계획으로 대체된 경우 등에, 끝나지 않은 작업이 있는데도 「완료」로 표시될 수 있음이 확인되어 있습니다. 아직 고쳐지지 않았습니다.
  3. Google 연결은 계정 하나를 함께 씁니다서버에 인증한 Google 계정 하나로 모든 사용자의 요청이 처리됩니다. 사용자별 계정 분리는 지원하지 않습니다.
  4. 명령 실행은 격리되어 있지 않습니다승인 절차는 있지만 명령은 서버에서 직접 실행됩니다. 신뢰할 수 있는 분리된 서버에서만 써야 합니다.
  5. 외부 서비스가 필요한 기능이 있습니다음악·영상 생성, 웹 검색 도구 등은 외부 서비스를 연결하기 전에는 동작하지 않으며, 그 사실을 화면에 표시합니다.

모델 제공사의 서버에서 돌아가는 모델을 인터넷으로 불러 쓰는 방식입니다. API 키는 그 서비스를 쓸 자격을 증명하는 비밀 열쇠입니다. 입력 내용은 제공사로 전송됩니다.

회사 안의 장비에 설치해 쓰는 모델입니다. 입력 내용이 회사 밖으로 나가지 않습니다. vLLM과 Ollama는 이런 모델을 구동하는 프로그램입니다.

먼저 시도한 방식이 준비되지 않았을 때 다음 방식으로 넘어가는 것입니다. 실제로 어떤 방식으로 처리되었는지 확인할 필요가 생깁니다.

자주 묻는 질문

우리 자료가 회사 밖으로 나갑니까?

어떤 기능을 쓰느냐에 따라 다릅니다. 프레임워크 어댑터와 협업 워크플로는 Anthropic, OpenAI, Google의 클라우드 모델을 쓰므로 입력한 내용이 해당 제공사로 전송됩니다. 사내 장비에서만 처리하려면 프레임워크 없이 「직접 실행」 방식에서 로컬 모델(Ollama)을 고르거나, 로컬 채팅을 씁니다. 부서 스킬은 로컬 모델을 먼저 쓰지만, 로컬 모델이 응답하지 않고 클라우드 API 키가 등록되어 있으면 클라우드로 넘어갑니다. 밖으로 나가면 안 되는 자료를 다룬다면 클라우드 API 키를 등록하지 않는 구성을 권합니다.

프레임워크 10종이 모두 바로 동작합니까?

10종 모두 연결 부품은 들어 있습니다. 다만 실제로 그 프레임워크로 실행되려면 해당 프레임워크가 서버에 설치되어 있고 필요한 API 키가 등록되어 있어야 합니다. 조건이 맞지 않으면 프레임워크를 거치지 않는 「직접 실행」으로 대체됩니다. 도입할 때 쓰려는 프레임워크를 정하고 설치 상태를 확인하시기를 권합니다.

사람은 무엇을 해야 합니까?

세 가지입니다. 맡길 일을 분명하게 적는 일, 실행 전에 계획을 확인하는 일, 그리고 결과를 검토해 확정하는 일입니다. 서버 명령 실행처럼 영향이 큰 작업은 승인 단계에서 사람이 결정합니다.

AI가 틀리면 어떻게 됩니까?

결과는 초안으로 다루어야 합니다. 검토 역할의 에이전트가 한 번 살펴보지만, 그것도 AI의 판단입니다. 조사 기능이 제시하는 출처와 수치에는 AI가 만들어 낸 것이 섞일 수 있고, 결과에 그 사실이 표기됩니다. 사실 관계와 수치는 담당자가 원자료와 대조해야 합니다. 실행이 실패한 경우에는 성공으로 표시하지 않고 오류 내용을 남깁니다.

Google Workspace를 연결하면 무엇을 주의해야 합니까?

연결하면 메일, 일정, 문서의 내용이 Google의 서비스와 오갑니다. 또 서버에 인증해 둔 Google 계정 하나로 모든 사용자의 요청이 처리됩니다. 로그인한 사람은 누구나 그 계정의 권한으로 메일을 읽고 보낼 수 있다는 뜻입니다. 개인 계정이 아닌 업무용 공용 계정을 쓰고, NexusAI 사용자 범위를 그 계정을 써도 되는 사람으로 제한하시기를 권합니다.

지금 쓰는 시스템을 바꿔야 합니까? 무엇을 준비합니까?

기존 시스템을 바꾸지 않습니다. NexusAI는 따로 설치해 웹 화면으로 씁니다. 준비할 것은 사용할 모델의 결정(클라우드 API 키 또는 로컬 모델을 구동할 GPU 서버), 사용할 프레임워크의 설치, 그리고 운영 환경 설정입니다. 로그인과 권한 검사는 운영 모드로 설정해야 모든 기능에 적용되므로 설치 후 반드시 확인합니다.

NexusAI는 무엇을 보증하고, 무엇은 보증하지 않습니까?

보증하는 것은 표시의 정직함입니다. 연결되지 않은 기능을 동작하는 것처럼 보이지 않고, 예시 데이터에는 예시라고 표시하며, 실패는 실패로 남깁니다. 협업 워크플로에서 같은 작업이 중복 실행되지 않는다는 점은 정해진 범위 안에서 모델 검사로 확인했습니다. AI가 낸 결과의 정확성과 클라우드 모델 제공사의 데이터 처리 방식은 보증하지 않습니다.

어떤 일을 AI 에이전트에게 맡겨 볼까요?

맡길 업무와 다루는 자료의 민감도에 맞춰 프레임워크, 모델, 연결 범위를 함께 정해 드립니다.
