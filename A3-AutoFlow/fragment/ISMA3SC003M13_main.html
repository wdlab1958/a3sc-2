Overview

매주 같은 문서,
처음부터 다시 씁니다

주간 보고, 회의 준비, 견적 검토, 문의 답변. 부서마다 형식은 정해져 있는데, 매번 빈 화면에서 다시 시작합니다.

인터넷의 AI 서비스에 맡기면 빠르지만, 계약서나 인사 자료, 매출 수치를 회사 밖으로 보내야 합니다. 그래서 많은 조직이 AI 사용을 막거나, 개인이 알아서 쓰도록 두고 있습니다. 어느 쪽이든 부서의 일하는 방식으로 자리 잡지 못합니다.

A3 AutoFlow는 글을 읽고 쓰는 AI(LLM, 대규모 언어 모델)를 회사 안의 서버에 설치해 씁니다. 부서별로 자주 하는 일을 「스킬」이라는 단위로 정리해 두고, 담당자가 화면에서 골라 실행하면 AI가 초안을 만듭니다. 스킬을 순서대로 이은 것이 「워크플로」이며, 정해진 시각에 자동으로 돌릴 수 있습니다.

쉽게 말하면

부서마다 초안을 먼저 써 두는 사내 보조 직원을 한 명씩 두는 것과 같습니다.

이 직원은 회사 건물 안에서만 일하고, 맡긴 일의 목록과 순서대로 초안을 써서 책상에 올려 둡니다. 다만 신입 직원의 초안처럼 틀릴 수 있으므로, 읽고 고치고 결재하는 일은 담당자가 합니다.
사내 자료를 다룰 때초안은 회사 안에서

대화, 스킬 실행, 워크플로 실행의 AI 처리는 사내에 설치한 언어 모델이 맡습니다. 외부로 나가는 경로는 「데이터 경로」에 따로 적었습니다.

부서마다 일이 다를 때부서별 업무 목록

11개 업무 계열, 19개 부서에 67개 스킬이 정리되어 있습니다. 부서 관리자가 이름과 설명을 적어 스킬을 추가하거나 고칠 수 있습니다.

매주 반복될 때정해진 시각에 실행

워크플로에 실행 주기를 정해 두면 그 시각에 스스로 돌고, 단계별 결과가 이력으로 남습니다. 필요할 때 직접 실행할 수도 있습니다.

AI에게 맡길 때확인은 사람이

AI가 만드는 것은 초안입니다. 실패한 단계는 실패로 표시되고, 누가 무엇을 바꾸고 실행했는지는 기록으로 남습니다.

How it works

업무를 고르면
초안이 나옵니다

담당자가 업무를 고르고 필요한 내용을 적으면, 사내 언어 모델이 초안을 씁니다. 여러 업무를 이으면 앞 단계의 결과가 다음 단계의 재료가 됩니다. 실행 결과는 이력으로 남고, 마지막 확인은 사람이 합니다.

  1. 업무 선택과 입력

    부서 화면에서 스킬을 고르고, 다룰 내용을 글로 적습니다. 대화 화면에서 평소 말투로 요청할 수도 있습니다.

    담당자
  2. 초안 작성

    스킬의 이름과 설명, 담당자가 적은 내용을 사내 언어 모델에 전달합니다. 모델은 요약, 초안, 분석을 한국어로 정리해 돌려줍니다.

    로컬 LLM
  3. 단계 잇기

    워크플로는 단계를 차례로 실행합니다. 앞 단계의 결과를 다음 단계에 넘겨, 분석에서 보고서 초안까지 한 번에 이어집니다.

    실행 엔진 · 자동
  4. 예약 실행

    실행 주기를 정한 워크플로는 그 시각에 자동으로 시작합니다. 같은 워크플로가 겹쳐 돌지 않도록 한 번에 하나씩만 실행합니다.

    스케줄러 · 자동
  5. 기록과 알림

    단계마다 성공과 실패, 결과와 오류가 이력에 남습니다. 일부라도 실패하면, 알림을 설정한 경우 메신저로 알립니다.

    이력 · 감사 기록
  6. 검토와 활용

    담당자가 결과를 읽고 사실과 수치를 확인한 뒤 고쳐 씁니다. 메일 발송이나 문서 공유는 담당자가 직접 실행합니다.

부서별 스킬 67개와 공통 스킬 8개

스킬은 「전표 분류」, 「영업 보고서」, 「회의실 예약」처럼 한 가지 업무를 가리키는 단위입니다. 담당자가 스킬을 실행하면 사내 언어 모델이 그 업무의 초안을 만듭니다. 스킬마다 전용 AI가 따로 있는 것이 아니라, 하나의 언어 모델이 스킬의 설명과 입력을 읽고 작성하는 방식입니다.

  • 경영·전략 — 경영기획, 사업개발
  • 재무·회계 — 전표 분류, 재무제표 분석, 예산 대비 실적
  • 인사 — 채용, 온보딩, 근태·급여, 교육, 평가 지원
  • 영업·마케팅 — 리드 평가, 영업 보고서, 계약서 검토
  • 구매·물류·총무 — 발주, 공급사 평가, 회의실·비품·문서 관리
  • 법무·감사, 고객 지원, 홍보·ESG, PMO, 기술·R&D, IT 운영·보안
  • 부서 관리자가 화면에서 스킬을 추가·수정·삭제
  • 목록에 없는 일은 AI 대화 화면에서 바로 요청

결과물담기는 내용쓰임새
스킬 실행 결과요약, 초안, 분석을 표와 목록으로 정리한 한국어 글. 확실하지 않은 부분은 가정을 밝히도록 지시되어 있습니다.보고서, 답변, 검토 의견의 출발점으로 씁니다.
워크플로 실행 결과단계별 상태와 결과, 오류 내용, 성공한 단계 수어느 단계에서 무엇이 나왔고 어디서 막혔는지 확인합니다.
실행 이력워크플로별 최근 실행 기록과 마지막 실행 시각, 누적 실행 수예약한 일이 실제로 돌았는지 점검합니다.
사용 현황최근 7일의 일별 실행 수, 성공률, 응답 지연, 구성 요소의 연결 상태어느 부서의 어떤 일이 자동화되고 있는지 봅니다.
감사 기록변경 요청, 스킬·워크플로 실행, 설정 변경의 시각과 내용누가 무엇을 바꾸고 실행했는지 되짚습니다.
실패 알림워크플로 이름, 실행 상태, 성공한 단계 수화면을 보고 있지 않아도 실패를 알게 됩니다. 설정한 경우에만 발송됩니다.

스킬은 회계·인사 같은 사내 업무 시스템에 직접 접속해 자료를 가져오지 않습니다. 담당자가 적어 넣은 내용과 앞 단계의 결과를 바탕으로 글을 씁니다. 따라서 결과에 담긴 수치와 사실은 원자료와 대조해야 합니다. 업무 시간 단축률 같은 효과 수치는 실측 기준이 없어 이 화면에 싣지 않았습니다.

Principle

돌지 않은 일을
완료로 적지 않는다

자동화 도구가 「완료」라고 표시할 때, 그것은 실제로 일이 끝났다는 뜻이어야 합니다.

A3 AutoFlow는 내부 점검을 거치며 이 기준에 맞게 고쳐졌습니다. 실행 결과는 단계별 실제 상태로 표시하고, 단계가 없는 워크플로는 「완료」가 아니라 「빈 흐름」으로 표시하며 실행 횟수에 넣지 않습니다. 화면의 실행 수는 실제 이력에서 다시 계산합니다. 아직 구현되지 않은 구성 요소는 화면에서 「예정」으로 구분해 보여 줍니다.

CASE · 형식 검증에서 찾은 결함

멈추라고 했는데 실행되는 틈

승인 절차의 감독 구조에 모델 검사를 적용했습니다. 승인을 기다리는 동안 운영자가 긴급 정지를 켜도, 승인이 들어오면 그대로 실행되는 결함이 발견되었습니다. 수정 전 코드에서 재현하고, 실행 직전에 긴급 정지를 다시 확인하도록 고쳤습니다.

  2. 자동 시작은 예약 실행만 지원합니다메일 수신이나 재고 변동 같은 사건을 감지해 스스로 시작하는 기능은 확인되지 않았습니다. 그런 흐름은 직접 실행합니다.
  3. 승인 절차는 화면에 연결되지 않았습니다승인 요청의 중복 발급, 승인 대기 시간 제한 등 3건은 기록해 두었고 설계 결정을 기다리고 있습니다.
  4. 부서별 권한 분리가 없습니다접근 통제는 공용 접근 키 하나입니다. 부서마다 볼 수 있는 범위를 나누는 기능은 구현되지 않았습니다.
  5. 구글 연동은 구글 계정의 권한으로 움직입니다화면에서 누른 발송과 삭제는 바로 실행됩니다. 연결할 계정과 권한 범위를 먼저 정해야 합니다.

LLMLarge Language Model · 대규모 언어 모델
많은 글을 학습해 문장을 읽고 쓰는 AI입니다. 요약, 초안 작성, 번역에 쓰입니다. 사실을 조회하는 도구가 아니어서 틀린 내용을 쓸 수 있습니다.
로컬 LLM · 온프레미스Local LLM · On-premise
언어 모델과 시스템을 외부 클라우드가 아닌 조직 내부 서버에 설치해 쓰는 방식입니다. 모델에 넣은 내용이 그 서버 안에서 처리됩니다.
스킬Skill
AI에게 맡기는 업무 한 가지입니다. 이름과 설명으로 이루어지며, 실행하면 그 설명에 맞는 초안이 나옵니다.
워크플로Workflow · 업무 흐름
여러 스킬을 순서대로 이은 것입니다. 앞 단계의 결과가 다음 단계로 넘어갑니다.
AI 에이전트AI Agent
정해진 역할 안에서 스스로 순서를 정해 일을 수행하는 AI 프로그램입니다. 이 플랫폼에서 현재 동작하는 것은 스킬을 실행하는 단계입니다.
예약 실행Cron · 스케줄러
「매주 월요일 오전 9시」처럼 정해 둔 시각에 일을 자동으로 시작하는 기능입니다.
Google Workspace구글 업무 도구 묶음
Gmail, 캘린더, 문서, 스프레드시트, 드라이브 등 구글이 제공하는 업무용 서비스입니다. 데이터는 구글의 서버에 있습니다.
계정 연결 동의OAuth
비밀번호를 넘기지 않고, 프로그램이 내 계정으로 할 수 있는 일의 범위를 허락하는 절차입니다. 구글 연동에 씁니다.
감사 기록Audit Log
누가 언제 무엇을 바꾸고 실행했는지를 남기는 기록입니다. 지우거나 고치지 않고 뒤에 덧붙이기만 합니다.
사람의 승인HITL · Human-in-the-Loop
자동화된 흐름 가운데에 사람의 승인을 넣는 방식입니다. 되돌릴 수 없는 일을 AI가 혼자 실행하지 않게 합니다.
긴급 정지Kill Switch
운영자가 켜면 진행 중인 자동 실행이 더 나아가지 않고 멈추는 스위치입니다.
모델 검사Model Checking · 형식 검증
프로그램의 동작 순서를 수학적 모형으로 옮겨, 정해 둔 범위 안에서 가능한 경우를 빠짐없이 따져 보는 검증 방법입니다.

자주 묻는 질문

우리 문서와 자료가 회사 밖으로 나갑니까?

기능에 따라 다릅니다. AI 대화, 스킬, 워크플로의 처리는 사내 서버에 설치한 언어 모델이 맡고, 실행 이력과 설정도 그 서버에 저장됩니다. 반면 Google Workspace 연동은 구글 계정으로 구글 서버와 직접 주고받는 기능이어서, 다루는 메일과 문서가 구글과 오갑니다. 메신저 알림을 켜면 워크플로 이름과 실행 상태가 메신저 서비스를 거칩니다. 이 외부 기능들은 설정하지 않으면 동작하지 않습니다.

사람은 무엇을 해야 합니까?

세 가지입니다. 첫째, 어떤 업무를 스킬과 워크플로로 등록할지 정합니다. 둘째, 실행할 때 다룰 내용을 적어 넣습니다. 셋째, 나온 초안을 읽고 사실과 수치를 확인한 뒤 고쳐서 씁니다. 보고와 발송, 결재는 사람의 일로 남습니다.

AI가 틀린 내용을 쓰면 어떻게 됩니까?

틀릴 수 있다는 전제로 씁니다. 결과는 초안으로만 제공되고, 스킬과 워크플로가 메일을 보내거나 문서를 고치지는 않습니다. 실행이 실패하면 실패로 표시되며 성공으로 바뀌어 보이지 않습니다. 다만 그럴듯하게 쓰인 틀린 문장을 시스템이 스스로 가려내지는 못하므로, 담당자의 검토가 필요합니다.

회계·인사 시스템이나 그룹웨어와 연결됩니까?

현재 스킬은 사내 업무 시스템에 직접 접속하지 않습니다. 담당자가 입력한 내용으로 초안을 만드는 도구이며, 기존 시스템을 대신하지 않습니다. 직접 연동되는 외부 서비스는 Google Workspace이고, 구글 업무 도구를 쓰지 않는 조직은 이 부분을 끄고 사용할 수 있습니다.

부서마다 필요한 업무가 다른데, 바꿀 수 있습니까?

바꿀 수 있습니다. 부서 화면에서 스킬을 이름과 설명으로 추가하고 수정하고 삭제합니다. 워크플로도 단계와 실행 주기를 정해 새로 만들 수 있고, 바꾼 내용은 서버를 다시 켜도 유지됩니다. 다만 부서별로 접근 권한을 나누는 기능은 아직 없습니다.

A3 AutoFlow는 무엇을 보증하고, 무엇은 보증하지 않습니까?

보증하는 것은 표시의 정직함입니다. 실행하지 않은 일을 완료로 표시하지 않고, 연결되지 않은 알림을 보낸 것처럼 표시하지 않으며, 구현되지 않은 구성 요소를 「예정」으로 구분합니다. 초안의 내용이 정확하다는 것, 업무 시간이 얼마만큼 줄어든다는 것은 보증하지 않습니다.

도입하려면 무엇을 준비해야 합니까?

언어 모델을 구동할 그래픽 처리 장치(GPU)가 달린 서버가 필요합니다. 모델의 크기에 따라 요구 사양이 달라집니다. 그리고 자동화할 부서 업무의 목록, 외부 연동(구글, 메신저)을 쓸지 여부, 접근을 허용할 범위를 함께 정합니다.

매주 되풀이되는 문서, 어느 부서부터 줄여 볼까요?

자동화할 업무 목록과 사내 설치 구성, 외부 연동 범위를 함께 정해 드립니다.
