Cluster-Master

쉬고 있는 PC 여러 대를,
하나의 연산 자원으로

Cluster-Master는 쓰지 않거나 사양이 낮은 PC 여러 대를 사내 네트워크로 묶어, 큰 계산을 나누어 처리하게 하는 분산 컴퓨팅 플랫폼입니다. PC의 운영체제 설치부터 작업 분배, 상태 감시까지를 한 화면에서 다루고, 일은 평소 쓰는 말로 지시할 수 있습니다. 위험한 명령은 사람의 확인을 거칩니다.

Overview

서버는 부족한데,
PC는 쉬고 있습니다

분석이나 AI 실험에 쓸 연산 자원은 늘 모자랍니다. 그런데 사무실과 연구실 한쪽에는 교체 시기를 넘긴 PC와 노트북이 꺼진 채 놓여 있습니다.

이 PC들을 묶어 쓰는 일은 생각보다 손이 많이 갑니다. 한 대씩 운영체제를 설치하고, 작업 프로그램을 깔고, 어느 PC가 살아 있는지 확인하고, 일을 나누어 주고 결과를 모아야 합니다. 대수가 늘수록 담당자의 시간이 그만큼 들어갑니다.

Cluster-Master는 이 과정을 한 대의 관리용 PC에서 처리합니다. 네트워크로 운영체제를 설치하고, 각 PC의 상태를 몇 초마다 받아 화면에 보여 주며, 일을 쪼개어 나누고 결과를 다시 모읍니다. 여러 대의 컴퓨터를 묶어 한 대처럼 쓰는 이런 구성을 클러스터라고 부릅니다.

쉽게 말하면

여러 사람이 서류 더미를 나누어 검토하는 사무실과 같습니다. 팀장이 서류를 나누어 주고, 자리에 있는 사람을 확인하고, 결과를 모아 한 권으로 묶습니다.

Cluster-Master에서 팀장은 관리용 PC(마스터)이고, 팀원은 묶인 PC(워커)입니다. 한 사람이 아무리 빨라도 혼자 하기 벅찬 일을 여럿이 나누면 빨라지지만, 나눌 수 없는 일은 빨라지지 않습니다. 컴퓨터도 같습니다.
방치된 PC를다시 일하게

64비트 CPU와 4GB 이상의 메모리, 유선 랜이 있는 PC면 작업용으로 쓸 수 있습니다. 새 장비를 사기 전에 가진 것부터 활용합니다.

한 대씩 하던 설치를네트워크로

PC를 랜선에 연결하고 켜면 운영체제와 작업 프로그램이 자동으로 설치됩니다. USB를 들고 자리마다 다닐 필요가 줄어듭니다.

코드 대신말로 지시

「1부터 100만까지 소수를 찾아 줘」처럼 적으면, AI가 일을 나누고 실행 코드를 만들어 각 PC에 보냅니다.

위험한 명령은사람이 확인

명령을 위험도에 따라 세 단계로 나눕니다. 상태를 바꾸는 명령은 확인을, 삭제나 재시작 같은 명령은 PIN 입력까지 요구합니다.

How it works

PC를 연결하고 일을 맡기면
결과가 모여 돌아옵니다

관리용 PC 한 대(마스터)가 나머지 작업 PC(워커)를 지휘합니다. 아래 여섯 단계 가운데 사람이 직접 하는 일과 자동으로 되는 일을 구분해 표시했습니다.

  1. PC 준비

    작업 PC를 관리용 PC와 같은 유선 네트워크에 연결합니다. PC마다 한 번, 설정 화면(BIOS)에서 네트워크 부팅을 켜 두고 전원을 넣습니다.

    사람 · PC마다 최초 1회
  2. 자동 설치

    PC가 네트워크로 부팅해 Ubuntu 운영체제를 내려받아 설치하고, 작업 프로그램을 받아 자동 실행되도록 등록합니다. 이미 Ubuntu가 깔린 PC는 네트워크 검색으로 찾아 작업 프로그램만 설치합니다.

    설치 서버 · 자동
  3. 합류와 상태 보고

    설치가 끝난 PC는 3초마다 「살아 있음」 신호와 CPU·메모리 사용률, 대기·작업 중 상태를 보냅니다. 화면에는 PC별 카드로 나타납니다.

    작업 PC · 자동
  4. 작업 지시

    화면에서 작업 수와 분배 방식을 고르거나, 하고 싶은 일을 문장으로 적습니다. 명령은 위험도에 따라 분류되어, 필요하면 확인이나 PIN을 묻습니다.

    사람이 지시하고 승인
  5. 분배와 실행

    AI가 일을 작은 단위로 쪼개고 각 PC가 실행할 코드를 만들어 보냅니다. 작업은 PC마다 차례대로, 또는 대기 작업이 가장 적은 PC부터 배정됩니다.

    AI 에이전트 · 작업 PC
  6. 감시와 취합

    실행 결과를 지켜보다 오류가 많으면 원인을 분석해 코드를 다시 만듭니다. 재시도는 세 번까지입니다. 끝나면 결과를 모아 보고서로 정리합니다.

    AI 에이전트 · 자동
자동으로 처리되는 단계사람이 직접 하거나 승인하는 단계
Features

설치, 지시, 감시를
한 화면에서 다룹니다

웹 브라우저로 여는 관리 화면은 여덟 개 탭으로 나뉩니다. 그 가운데 도입을 검토할 때 먼저 살펴볼 다섯 가지를 골랐습니다.

말로 지시하는 AI 지휘

작업을 문장으로 적으면 다섯 역할의 AI 에이전트가 차례로 일을 넘겨받습니다. 에이전트가 어떤 순서로 무엇을 판단했는지는 화면에 실시간으로 남습니다. AI 언어 모델은 사내에 설치한 것을 먼저 쓰고, 연결된 모델이 없으면 실패로 알립니다. 미리 준비된 예제로 흐름만 보여 주는 시뮬레이션 모드는 운영자가 따로 켰을 때만 동작하고, 결과에 시뮬레이션 표시가 붙습니다.

  • Planner — 지시를 세부 작업으로 분해
  • Coder — 각 PC가 실행할 Python 코드 작성
  • Deployer — 만든 코드를 작업 PC에 전달
  • Monitor — 결과 감시, 오류 시 재작성 요청
  • Aggregator — 결과를 모아 보고서 작성
  • 40여 가지 오류 유형을 분석해 재시도에 반영

네트워크 자동 설치

관리용 PC가 설치 서버 역할을 해, 작업 PC가 네트워크로 부팅하면 사람의 입력 없이 설치가 끝납니다.

  • 설치에 필요한 설정 파일을 화면에서 생성
  • PC별 설치 진행 상황 표시
  • 관리용 PC의 주소·게이트웨이 자동 감지
  • 이미 Ubuntu가 깔린 PC는 네트워크 검색으로 등록

상태 화면과 작업 분배

묶인 PC가 지금 대기 중인지, 일하는 중인지, 응답이 없는지를 한 화면의 카드로 보여 줍니다.

  • 최대 50대를 격자로 표시
  • PC별 CPU·메모리 사용률
  • 차례대로 / 대기 작업이 적은 PC 우선 분배
  • 작업 결과의 실시간 기록

명령 승인과 감사 기록

명령을 100여 개 규칙으로 분류합니다. 조회는 바로 실행하고, 변경은 확인을 받고, 삭제·재시작 같은 명령은 PIN까지 요구합니다.

비용 분석가동 중인 PC 수를 기준으로 계산한 운영 비용과 클라우드 이용 시 예상 비용의 비교도입 효과를 설명하는 참고 자료로 씁니다.

비용 분석의 금액은 가동 중인 PC 수와 입력한 전기 요금으로 계산한 추정치이며, 실제 청구액이나 절감액을 보증하지 않습니다. PC별 효율 지표 가운데 측정할 수 없는 항목은 값을 채워 넣지 않고 비워 둡니다. GPU가 감지되지 않으면 목록은 비어 있는 그대로 표시됩니다.

Principle

되는 것보다
안 되는 것을 먼저

여러 대를 묶어 쓰는 시스템에서 가장 곤란한 것은, 실제로는 돌지 않았는데 화면에는 성공으로 나오는 경우입니다.

Cluster-Master는 두 차례의 코드 감사를 거치며 이런 지점을 찾아 고쳤습니다. 작업 PC가 한 대도 없는 상태의 배포 결과에는 시뮬레이션 표시가 붙습니다. 격리 실행 환경이 없으면 「실행되지 않음」으로 알립니다. 상태 저장소가 멈추면 빈 목록을 정상인 것처럼 내보내지 않고 오류로 응답합니다. 아래는 형식 검증에서 찾아 고친 결함과 현재의 한계입니다.

CASE · 형식 검증에서 확인된 결함

멈춘 PC가 살아 있는 것으로 남는 경우

각 PC는 3초마다 신호를 보내고, 10초 동안 신호가 없으면 목록에서 빠지도록 설계되어 있습니다. 가능한 실행 순서를 빠짐없이 따져 보는 모델 검사에서 이 약속이 깨지는 경우가 2건 확인되었습니다. 작업 프로그램만 멈추고 PC는 켜져 있을 때, 관리용 PC의 점검 기능이 그 PC를 계속 정상으로 표시해 작업이 그쪽으로 배정된 채 처리되지 않고 쌓일 수 있습니다. 또 점검 시점이 겹치면 PC의 최신 상태 표시가 잠시 이전 값으로 덮일 수 있습니다.

FIXED두 결함 모두 실제 코드에서 재현한 뒤 고쳤습니다. PC의 생존 신호는 그 PC의 작업 프로그램만 갱신하고, 이전 값이 최신 값을 덮지 못하게 했습니다. 정해 둔 범위 안에서의 확인이며, 여러 대의 실제 PC에서 장시간 운영한 검증은 아직 하지 않았습니다.
LIMITS · 현재의 한계
  1. 재배정은 모의 환경에서만 확인했습니다작업을 받은 PC가 꺼지면 그 작업을 다른 PC에 다시 배정합니다. 한 장비 안에서 프로그램 여러 개로 시험한 결과이며, 실제 여러 대의 PC에서는 아직 검증하지 않았습니다.
  2. 나눌 수 있는 일에 맞습니다여러 조각으로 쪼개어 따로 계산할 수 있는 작업이 대상입니다. 여러 PC에 걸친 AI 모델 분산 학습은 구현되어 있지 않으며, GPU 서버를 대신하지 않습니다.
  3. 작업 코드는 격리된 컨테이너에서 실행됩니다작업 PC에 Docker 같은 격리 수단이 없으면 코드 작업을 받지 않습니다. 그래도 작업 PC는 중요한 자료가 없는 전용 장비로 두는 구성을 권합니다.
  4. 시뮬레이션 결과는 따로 표시됩니다결과를 받지 못한 작업은 실패로 남습니다. 시뮬레이션 모드는 운영자가 켰을 때만 동작하고, 결과마다 시뮬레이션 표시가 붙습니다.
  5. 자동 증설과 장애 대비는 일부만 동작합니다PC를 늘려야 한다는 판단과 알림은 나오지만 실제 추가는 사람이 합니다. 부하 분산·장애 차단 기능은 여러 대의 실제 환경에서 전체 동작을 검증하지 않았습니다.

Glossary

쉽게 풀어 드립니다

이 화면에 나오는 용어를 전공자가 아니어도 읽을 수 있게 정리했습니다.

클러스터Cluster
여러 대의 컴퓨터를 네트워크로 묶어 한 대처럼 쓰는 구성입니다. 한 대로는 오래 걸리는 계산을 나누어 처리합니다.
노드 · 마스터 · 워커Node · Master · Worker
노드는 클러스터에 속한 컴퓨터 한 대입니다. 일을 나누어 주고 지휘하는 한 대가 마스터, 받은 일을 실제로 계산하는 나머지가 워커입니다.
분산 처리Distributed Computing
큰 일을 작은 조각으로 쪼개 여러 컴퓨터가 동시에 처리하고 결과를 합치는 방식입니다. 쪼갤 수 없는 일에는 효과가 없습니다.
하트비트Heartbeat · 생존 신호
각 PC가 「살아 있음」을 알리려고 일정한 간격으로 보내는 신호입니다. Cluster-Master에서는 3초마다 보냅니다.
리스Lease · 유효 시간이 있는 등록
「이 PC는 살아 있다」는 등록에 유효 시간을 붙여 두는 방식입니다. 신호가 끊겨 시간이 지나면 등록이 저절로 사라지도록 하려는 장치입니다.
스케줄링 · 로드 밸런싱Scheduling · Load Balancing
어떤 일을 어느 PC에 언제 맡길지 정하는 것이 스케줄링이고, 한 PC에 일이 몰리지 않게 고르게 나누는 것이 로드 밸런싱입니다.
네트워크 부팅PXE Boot
PC가 자기 디스크가 아니라 네트워크에서 설치 프로그램을 받아 켜지는 방식입니다. USB 없이 여러 대에 같은 운영체제를 설치할 수 있습니다.
AI 에이전트AI Agent
정해진 역할 안에서 스스로 판단해 일을 수행하는 AI 프로그램입니다. 여기서는 계획, 코드 작성, 배포, 감시, 취합의 다섯 역할이 있습니다.
로컬 LLMLocal Large Language Model
외부 클라우드가 아니라 조직 안의 장비에 설치해 쓰는 AI 언어 모델입니다. 지시 내용이 밖으로 나가지 않습니다.
시뮬레이션 모드Simulation Mode
운영자가 켰을 때 미리 준비된 예제로 흐름만 보여 주는 상태입니다. 실제 계산 결과가 아니며, 결과마다 시뮬레이션 표시가 붙습니다.
샌드박스Sandbox · 격리 실행 환경
코드를 다른 프로그램과 분리된 공간에서 실행해, 문제가 생겨도 바깥에 영향을 주지 않게 하는 장치입니다. 네트워크를 끊고 CPU·메모리·시간에 한도를 둡니다.
모델 검사Model Checking · 형식 검증의 한 방법
여러 프로그램이 동시에 움직일 때 생길 수 있는 실행 순서를 정해진 범위 안에서 빠짐없이 따져, 약속이 깨지는 경우를 찾는 검증 방법입니다.

자주 묻는 질문

작업 내용이나 데이터가 회사 밖으로 나갑니까?

PC 사이의 작업 전달과 상태 보고는 사내 네트워크 안에서 이루어집니다. AI 언어 모델은 사내에 설치한 모델(Ollama, vLLM)을 먼저 쓰도록 되어 있고, 이때 지시 내용은 밖으로 나가지 않습니다. 다만 사내 모델이 없고 외부 AI 서비스(OpenAI)의 키를 설정해 둔 경우에는 지시 내용이 그 서비스로 전송됩니다. 키를 설정하지 않으면 호출되지 않습니다. Telegram·Discord 연동을 켜면 상태 알림과 명령이 해당 메신저 서비스를 거칩니다. 두 기능 모두 선택 사항입니다.

사람이 해야 하는 일은 무엇입니까?

처음에는 PC를 유선 네트워크에 연결하고, PC마다 한 번 네트워크 부팅을 켜고, 전원을 넣는 일입니다. 운영 중에는 작업을 지시하고, 확인이나 PIN을 요구하는 명령을 승인하고, 결과가 빠짐없이 돌아왔는지 확인합니다. 고장 난 PC를 교체하거나 PC를 늘리는 일도 사람이 합니다. 「전원만 켜면 끝」은 설치 과정에 한한 이야기입니다.

쓰던 PC에 들어 있는 자료는 어떻게 됩니까?

네트워크 자동 설치는 작업 PC의 디스크를 지우고 Ubuntu를 새로 설치합니다. 기존 Windows와 파일은 남지 않습니다. 필요한 자료는 미리 옮겨 두어야 하고, 업무에 쓰는 PC는 작업 PC로 묶지 않아야 합니다. 이미 Ubuntu가 설치된 PC는 디스크를 지우지 않고 네트워크 검색으로 찾아 작업 프로그램만 설치할 수 있습니다.

AI가 만든 코드가 틀리면 어떻게 됩니까?

돌아온 결과 가운데 오류가 절반을 넘으면 감시 역할의 에이전트가 원인을 분석해 코드 작성 역할에 다시 요청하고, 세 번까지 재시도합니다. 오류 없이 실행되었지만 결과가 틀린 경우는 시스템이 알아차리지 못할 수 있습니다. 보고서에 계획과 생성된 코드가 함께 남으므로, 중요한 결과는 사람이 코드와 값을 검토해야 합니다.

작업 도중 PC가 꺼지면 어떻게 됩니까?

신호가 끊긴 PC는 응답 없음으로 표시되고, 다른 PC들은 계속 일합니다. 꺼진 PC가 처리하던 작업은 자동으로 다른 PC에 다시 배정되지 않습니다. 또 모델 검사에서, 작업 프로그램만 멈춘 PC가 정상으로 표시된 채 남아 작업이 그쪽에 쌓일 수 있는 결함이 확인되어 설계를 보완하고 있습니다. 그래서 결과가 하나라도 빠지면 안 되는 작업은 완료된 수를 확인하고 빠진 부분을 다시 실행하는 절차를 함께 두어야 합니다.

GPU 서버를 사지 않아도 됩니까?

용도에 따라 다릅니다. 여러 조각으로 나누어 CPU로 계산할 수 있는 작업이라면 가진 PC로 처리할 수 있습니다. 대형 AI 모델을 학습시키는 일처럼 GPU의 연산 능력이 필요한 작업은 낡은 PC 여러 대로 대신할 수 없습니다. PC에 NVIDIA GPU가 달려 있다면 그 GPU를 찾아 상태를 보여 주고 작업에 할당하는 기능은 제공합니다.

무엇을 보증하고, 무엇은 보증하지 않습니까?

말씀드릴 수 있는 것은 확인된 범위입니다. 두 차례의 코드 감사에서 찾은 문제를 고쳤고, 추정치에는 추정이라는 표시가 붙으며, 알려진 결함과 한계는 이 화면에 적은 그대로입니다. 시뮬레이션 결과에는 표시가 붙습니다. 보증하지 않는 것은 모든 작업이 빠짐없이 한 번씩 처리된다는 것, PC 대수만큼 속도가 빨라진다는 것, 비용이 얼마 절감된다는 것입니다. 형식 검증의 통과도 정해진 범위 안에서 반례가 없다는 뜻이며 코드 전체가 옳다는 뜻은 아닙니다.

쉬고 있는 PC, 몇 대나 있습니까?

가진 PC의 사양과 맡기려는 작업을 알려 주시면, 묶어 쓸 수 있는 범위와 구성을 함께 살펴 드립니다.
